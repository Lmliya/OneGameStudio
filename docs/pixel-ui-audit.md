# OneGameStudio Pixel UI 与 2.5D 场景审计

> 审计日期：2026-10-25。本文只记录当前代码事实与本次视觉改造范围，不把不存在的业务页面列为已交付功能。

## 1. 当前实现

- 技术栈：原生 HTML、CSS、JavaScript、Canvas 2D；无框架、无构建步骤，FastAPI 直接托管 `frontend/`。
- 页面结构：顶部公司 HUD；左侧办公室与 CEO 指令台；右侧游戏、企划、审查、宣传、员工、日志六个标签；底部公司广播。
- 状态管理：`app.js` 的全局 `state`、`office.js` 的员工状态 Map、`talent.js` 闭包；任务由 WebSocket 快照与增量事件恢复。
- 素材：运行时没有外部 PNG 精灵或像素字体；现有角色、家具、Logo 和图标均为原创 Canvas/CSS 图形。
- 设计变量：`style.css` 已集中定义奶油纸面、木色、状态色、硬边框与阶梯阴影；Canvas 仍另有一套硬编码色值。

## 2. 办公室缺乏空间深度的原因

1. 原 `AGENTS` 的 `x/y` 是固定屏幕像素，不是世界坐标，无法表达前后移动。
2. 地板使用水平矩形木纹，地毯、家具和墙面均按正视图绘制，没有 2:1 等距投影。
3. 桌面、柜体等主要是正面矩形，缺少顶面、左右侧面、厚度和桌腿之间的遮挡。
4. 原排序只按屏幕 `y` 排列整个工位；人物、桌子和椅子被绑定为固定绘制次序，不能根据人物在桌前/桌后的世界位置改变遮挡。
5. 热区层虽与人物共用屏幕坐标，但场景缩放、拖动画布与更精细的角色命中需要统一的屏幕到世界对象映射。

## 3. 可复用部分

- `Office.setAgent / setRequirement / setSpeech / setTag / resetAgents / onSelect / drawPortrait` 是现有跨文件接口，必须保留。
- 六个岗位 ID 与后端 `agent.status_changed` 事件契约不变。
- `Office.onSelect` 到 Employee 标签的入口不变；Engineer 继续进入当前岗位启用角色，可使用原有主/备切换按钮。
- `drawHead` 的角色配色、发型和表情可复用到新人物与档案头像。
- 静态房间缓存、Canvas `imageSmoothingEnabled = false`、CSS `image-rendering: pixelated` 可继续使用。
- 全站 `.panel`、`.block`、`.badge`、`.verdict`、`.tag`、`.metric-row`、`.mini-btn` 已是设计系统雏形。

## 5. 需要新增的视觉资源

- 原创等距地板、两面开放墙、地毯与会议区。
- 有顶面/侧面/桌腿的六套工位，带厚度与支架的状态显示器。
- 六岗位统一比例人物；复用备用工程师头像配色。
- 柜子、绿植、书架、会议桌、沙发等原创程序化 Sprite。
- 场景工具条：缩小、缩放读数、放大、复位；不需要外部素材或 3D 引擎。

## 6. 交互与实现风险

- 必须使用 `worldX/worldY/worldZ → screenX/screenY` 单一投影，命中区由投影后的角色/工位包围盒生成，不能另写一套坐标。
- 拖拽与点击必须区分，避免拖动画布后误开员工档案。
- 缩放要限制范围，鼠标指针位置与 canvas CSS 尺寸、DPR 之间必须正确换算。
- 动画只改变表现，不生成后端不存在的状态或进度；`prefers-reduced-motion` 下停用装饰运动。
- 保留现有单页生命周期；不重复绑定 WebSocket，不引入页面切换监听器泄漏。
- 空闲时只响应 dirty 重绘；活动状态限制动画帧率，页面隐藏时停止绘制。
- 窄屏允许办公室视口横向滚动和按钮缩放，不把文字缩到不可读。

## 7. 既有业务边界（不在本次修改范围）

- 后端 Engineer 工作流当前固定使用 `engineer`，岗位切换只写岗位指针；本次不改调度、接管或 API。
- 自动接管开关当前不存在，不能伪造为已实现。
- 本次不处理审计中发现的 Demo artifacts、Live 令牌、异步响应时序等既有业务问题；它们与视觉升级无关，应另立修复任务。
- `AGENTS.md` 当前不存在，已以 README、HANDOFF、architecture、ui-layout-migration 和实际源码为准。

## 8. 2.5D 改造结果与验收（2026-10-25，未提交）

### 8.1 等距投影与空间实现

- `frontend/office.js` 重写为真正的 2.5D 场景：所有地板、墙体、家具、人物使用统一的 `worldX/worldY/worldZ → screenX/screenY` 2:1 等距投影（`tileW=64, tileH=32, heightScale`），不再写死屏幕坐标。
- 房间为开放双墙结构：等距地板网格、左右两面带窗墙体、踢脚线与环境光影；家具（办公桌、显示器、椅子、书柜、沙发、会议桌、绿植、地毯）均有顶面、侧面、厚度与桌腿，按世界坐标绘制。
- 深度排序：静态家具与墙体按世界深度排序绘制；人物按自身世界 `y` 独立插入排序序列，人物绕到桌后可被桌面正确遮挡，走到桌前则显示在桌面前方。
- 人物：六岗位统一比例原创像素小人，带待机/工作/思考/完成/错误状态动画（帧动画 + 状态气泡），与后端 `agent.status_changed` 事件绑定；显示亮光、接触阴影均为硬边像素风格。
- 命中检测：6 个 DOM 热区由场景投影实时生成，与 Canvas 绘制共用同一坐标变换（含缩放、拖动、DPR），缩放范围 0.75×–1.75×，支持拖动画布与一键复位，读数 `#office-zoom`。
- 性能：静态房间离屏缓存，仅状态变化或相机变化时重绘；`prefers-reduced-motion` 下停用装饰动画；DPR 上限 3。

### 8.2 全站像素 UI

- `style.css` 完善 Design Tokens（`--bg/--surface/--surface-2/--ink/--accent/--warn/--danger` 等，兼容旧变量名），统一 HUD、面板、标签、按钮、输入、下拉、表格、卡片、日志终端、街机预览框、员工档案卡的像素边框、阶梯阴影与硬边风格。
- 游戏预览仅统一外壳（街机屏），iframe 沙箱属性不变，不注入像素 CSS。
- 逐页面结论见第 4 节表格；版本并排比较、Talent 自进化、设置、自动接管仍为 NOT_APPLICABLE（业务不存在，未伪造）。

### 8.3 真实浏览器验收结果（Edge headless，APP_MODE=live + MOCK_MODE=true）

- 截图：`docs/screenshots/pixel-ui/office-1920x1080.png`、`office-1366x768.png`、`office-1280x720.png`、`office-narrow-900.png`、`office-hidpi.png`（DPR=2）、`talent-detail-engineer.png`。
- 布局：1920/1366/1280 无溢出；≤980px 单列可纵向滚动，900/640/480 宽度均无横向溢出。
- 点击命中：coo / creative / delivery / engineer / reviewer / marketer 六个热区逐一点击，员工档案均打开对应角色 → 6 项 PASS。
- Engineer 面板：「设为启用」主/备切换控件存在且样式统一；缩放 + 后读数 155%，复位回到自适应 130%（1366 视口）。
- 控制台：整个验收过程无 `pageerror`。
- 回归：`uv run pytest -q` → 96 passed / 26 failed；对未改动代码（git stash 基线）复测同一批测试同样失败，确认这 26 项为既有后端/环境失败（机械门禁、SOP 场景、工作流等），与本次前端视觉改造无关。
